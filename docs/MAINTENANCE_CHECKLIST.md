# Maintainer Checklist

This checklist captures the major practices Duesora must continuously
maintain.

1.  Keep repository structure predictable.
2.  Keep README accurate.
3.  Keep installation easy.
4.  Maintain `.env.example`.
5.  Maintain an explicit license.
6.  Maintain contributing guidance.
7.  Use meaningful commit conventions.
8.  Protect the default branch.
9.  Require automated CI.
10. Maintain unit/integration/E2E tests.
11. Treat security as a dedicated process.
12. Never store provider passwords.
13. Use explicit database migrations.
14. Preserve backward compatibility where promised.
15. Use semantic versioning.
16. Maintain a changelog.
17. Maintain actionable issue templates.
18. Maintain useful labels.
19. Keep a public roadmap.
20. Maintain user and developer documentation.
21. Document/version public APIs.
22. Maintain structured observability.
23. Provide health/readiness checks.
24. Maintain backup and restore procedures.
25. Avoid mandatory paid dependencies.
26. Maintain accessibility.
27. Measure and protect performance.
28. Preserve self-hosting as a first-class path.
29. Maintain consistent branding.
30. Maintain a respectful, responsive contributor community.

## Release review

Before every release, explicitly review all 30 areas and record
exceptions as issues.
