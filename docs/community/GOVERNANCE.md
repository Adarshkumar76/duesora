# Governance

## Current model

Duesora begins as a maintainer-led open-source project.

## Roles

### Contributor

Anyone who submits useful code, documentation, design, testing,
translations, or issue analysis.

### Maintainer

Trusted contributor with review/triage responsibilities.

### Core maintainer

Responsible for architecture, releases, security response, repository
policy, and final decisions.

## Decision principles

1.  User safety and data integrity.
2.  Security and privacy.
3.  Backward compatibility.
4.  Simplicity and maintainability.
5.  Self-hosting quality.
6.  Community usefulness.
7.  Performance and convenience.

Large architectural changes should have a written ADR before
implementation.

## Becoming a maintainer

Maintainer access should be earned through sustained, high-quality
contributions and responsible project participation. Access follows
least privilege and may be reviewed or removed when no longer needed.
